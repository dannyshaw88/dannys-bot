## Avoid Users Containing dismissals

When Add Friends' “Avoid Users Containing” filter matches a suggestion, target the `friend-cell-dismiss` Hide control inside that exact friend row. A saved X is valid only when its screen dimensions match, it falls inside the live Hide-node bounds, and it is clear of the live Add button; otherwise tap the exact live Hide-node center. Use the Hide node's own center Y. Do not add a second manual scroll after a successful Hide tap; Snapchat refreshes the list and moves it up by one contact.

**Why:** Snapchat's Hide action refreshes the list and shifts it by one slot, so an extra swipe would skip another contact. A device log also showed a saved dismiss X being tapped without validating it against the live Hide node; the code then reported “dismissed” without checking the resulting list, even though the user observed that the person had been added.

**How to apply:** Find the Hide control by `friend-cell-dismiss` and its position inside the matched row. Validate any saved X against that live node and the Add button; otherwise use the Hide node center. After the tap, inspect the refreshed UI and report whether the name remains or is no longer visible; never claim dismissal just because ADB accepted a tap. Then rescan without a second swipe. If no Hide node is exposed, scroll past the row using its live node height.

Open Add Friends from Camera by locating the live `neon_add_friend_button_container` or the accessible “Add friends” label and its clickable parent. A banner obstruction must be a top overlay identified by Snapchat's incoming-event copy (such as “is typing” or “sent you a Snap”), a banner/toast/notification resource or class, or Android System UI. Its bounds must cover the icon's tap point. Never infer a banner from generic clickability, text, or overlap geometry alone: a normal “Flip Camera” accessibility group can span across the Add icon. If a real banner overlaps the icon's tap point, wait five seconds and recheck up to ten times. Tap immediately after a clear check; if still covered at check ten, skip only Add Friends rather than aborting the cycle. Do not use deep links, internal activity launches, fixed coordinates, or a fixed device serial. On the Find Friends list, use the current UI dump's matched row and tap its live Add button directly; do not traverse keyboard Tab focus between friends. The user's Tab exploration applied only to the Camera-screen icon. For an Add or skipped row that remains visible, estimate the target movement from the median divider-to-divider height of fully visible middle contact rows, excluding the top and bottom contacts. After each slow swipe, compare the same contact labels' live row positions before and after; adjust using the measured content movement and a per-device ratio rather than assuming finger travel equals list travel. Exclude Add buttons below 85% of screen height, and keep scroll endpoints above 82%, so the next tap stays clear of Android's bottom navigation. Count a matched Find Friends row's Add action without requiring Snapchat to replace the label or show a confirmation. If a measured scroll cannot be placed or verified, continue with other currently visible unattempted rows. A successful Hide tap needs no extra swipe because Snapchat refreshes the list by one contact. If an incoming banner redirects the flow to a chat/composer, back out without typing, restore Add Friends, and retry that same row; after repeated interruptions, skip only that row and continue the cycle.

**Why:** The inspect dump showed the broad geometric test matching the normal “Flip Camera” group because its bounds crossed the Add icon. The user means Snapchat's brief incoming-Snap/typing banner, not arbitrary camera controls. The user also requires at most ten checks, no global 60-second Snapchat idle abort, and no Tab navigation through friend rows; Tab was only explored for opening Add Friends from Camera. A live Add Friends screen showed lower-row Add controls near Android navigation, where an ad can obscure them. The user rejected treating finger travel as content movement because Android's list scrolls farther than the gesture. UIAutomator does not expose the grey separators as nodes; using a contact's node bounds as the requested line-to-line pixel measurement is not equivalent and must not be claimed as such. The user explicitly requires one screenshot and one line-to-line measurement per scroll, then one swipe using exactly that measured pixel distance; repeated screenshots and iterative correction violate this. Never swipe down the row center: the name/avatar can receive it as a tap instead of scrolling. Use a node-verified blank side margin or refuse to swipe. A successful Hide already shifts the list and must not get an extra swipe.

**How to apply:** Resolve the live icon from its resource ID or “Add friends” accessibility label, including its clickable parent. In the latest UI dump, require incoming-event text or a banner/notification identifier on a top overlay that covers the tap point; generic camera accessibility groups must never qualify. Do not add another device query between a clear result and the tap. Log each numbered banner check. After ten blocked checks, skip only this tool. For each friend row, identify the name, live row bounds, and Add button from one fresh dump; tap the button directly without Tab traversal. Capture one current device screenshot and measure the actual grey divider pixels above and below one fully visible middle contact; use exactly that native-pixel gap for one swipe. If the screenshot or separator pair is unavailable, fail closed instead of substituting accessibility row height. Do not take post-swipe screenshots or run iterative corrections. Swipe along a node-verified blank side margin rather than across any contact content; if no safe lane is exposed, refuse the swipe. Keep Add Friends and Accept Friends implementations in their separate tool-owned files. Preserve the live row-to-button identity match and attempted-row history. Do not count a change of Add label as required confirmation. On an unexpected chat surface, use Back to dismiss the keyboard and leave the chat, then return to Add Friends before retrying.
